== Accepted UX baseline

* Desktop application presentation mode remembered per app, account and device.
* Chat windows detached only on explicit user action.
* Desktop supports both host-menu detach and drag-to-detach, sharing one permission-checked transition.
* Tablet uses adaptive split panes and multiple floating panels, with safe resource limits and fallback.
* Closing a view preserves bounded resumable state but does not grant background execution.
* Phone remains embedded with reliable one-action return to messaging.

== Shared interface and security constraints

* `tavix.presentation/v1` is an app preference declaration, not a permission.
* `tavi.workspace/v1` is host-mediated. No TaviX code may directly call unrestricted OS window APIs.
* `tavix.session-context/v1` binds account session, reviewed package digest, app identity, instance, surface and grants. It is not an exportable credential.
* `workspace.surface.present` is used for menu and drag; an optional `inputMethod` is diagnostic only and never authorizes.
* Chat opening in a separate window requires a host-recorded user gesture; app-initiated popups cannot bypass this.
* All privileged LoopRD/Asset Studio operations remain server-authorized and are independent of presentation.
* No administrative token, bearer credential, unapproved publish decision or wallet mutation is stored in resume state.

== Outstanding technical choices

* Adaptive surface limits, memory-pressure fallback and retention bounds.
* Exact drag affordance, snap zones and keyboard accessibility alternatives.
* Persistence schema and device-local retention/cleanup policy.
* Native window transport and bridge reconnect implementation.

These are implementation design decisions, not reasons to reopen the accepted UX choices.
