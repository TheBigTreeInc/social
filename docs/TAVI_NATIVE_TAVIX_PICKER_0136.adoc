= Tavi 0.3.136 — Native local TaviX chooser repair
:revnumber: 0.3.136
:toc:

== Report

On a LoopRD-authorized Developer Mode account in Tavi 0.3.135, selecting
"Install .tavix" appeared to do nothing. Source review found that the Apps
button programmatically called `.click()` on `<input type=file hidden>`. The
specific failing WebView condition has not been reproduced in this authoring
environment; a synthetic click on an invisible input is a fragile native file
picker trigger.

== Change

* Render a styled label with a real file input covering its interactive area;
  Windows WebView2/Android WebView receive the direct user gesture rather than
  a JavaScript-proxied click on a display:none element.
* Keep the clickable input accessible, keyboard focusable, and at least 44px
  high on touch devices; use `:focus-within` indication.
* Clear `input.value` after each `change` event so the same `.tavix` file may
  be selected repeatedly. Cancel means no import; no credentials or file
  paths are logged.
* Check the current developer gate on click and selection. Recheck the current
  authenticated LoopRD developer permission before parsing, and again before
  install approval. Deny on stale session, account change or permission revoke.
* Report missing app-storage scope explicitly instead of silently returning.
* No new native dependency or expanded permissions. Package ZIP validation,
  sandbox privileges, first-party shadow isolation and published catalog
  permissions remain unchanged.
